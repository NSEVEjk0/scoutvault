# ScoutVault walkthrough

Target **2:30** with English narration and captions. Follow one sample rental check through the public app. Use the buyer and scout test wallets, label the sample image, and show the real transaction in Solana Explorer. Use only product, listing, and Explorer footage.

| Time and screen | Narration |
| --- | --- |
| 0:00–0:15. Open ScoutVault’s map. | A rental listing can promise running water without showing the tank. ScoutVault lets you ask someone nearby to check the place before you send a deposit. |
| 0:15–0:25. Open the sample Akoka studio listing. | This sample studio in Akoka lists an address, a yearly price, and a water tank. I’m using test tokens on Solana devnet. |
| 0:25–0:45. Read the link, then edit the checklist. | I paste the listing link. Firecrawl reads the page, and ScoutVault turns those three details into questions. I can edit each question and move the entrance pin. |
| 0:45–1:05. Review costs and fund two test tokens. | I set the reward at two test tokens. The Solana program holds them for this check, so the scout can see the reward is funded before accepting. |
| 1:05–1:25. Switch to the scout and claim. | I switch to the scout wallet and claim the check. Only one scout can claim it. The scout can read the questions or have the device read them aloud. |
| 1:25–1:48. Answer the questions and attach the sample image. | The scout answers each question and attaches a photo. Here I’m using a labelled illustration. The water tank stays marked as unconfirmed. |
| 1:48–2:13. Sign, inspect the verified report, and approve. | The scout signs the report. ScoutVault checks the photo and signature against what was submitted. The requester sees the answers and approves this exact report. |
| 2:13–2:25. Show payout in Solana Explorer. | The scout’s balance increases by two tokens. Solana Explorer shows the devnet payout and its confirmed transaction. |
| 2:25–2:30. Return to the paid check. | The requester now has the signed report and the payout receipt. |
