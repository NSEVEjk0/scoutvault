# Validation record

The compiled Anchor program passed seven local-validator scenarios: exact funding and payout, buyer self-claim rejection, exclusive scout assignment, report and payment authorization, changed-report rejection, refund and ID-reuse protection, dispute authority, and unsolicited vault donations. Several checks run within the same scenario.

Three server checks passed for private and credential-bearing URL rejection, captured-source receipt tampering, and canonical report encoding. The complete API exercise funded a two-token bounty, claimed it, signed and stored a sample report, blocked anonymous photo access, preserved the original photo hash, approved the exact report, and verified a two-token increase in the scout's balance.

All three hosted browser checks passed against the public local demo. They covered desktop and phone layouts, contrast, keyboard focus, reduced motion, and a complete buyer-to-scout payout. A recording then exposed a request that could run before configuration was loaded when opening a bounty directly. The API bootstrap now waits for a shared configuration request. The updated buyer/scout check passed again, including a full page reload and re-verification of the private report.

The web production build and TypeScript checks passed. GitHub's build and server checks passed for the initial public source. The finished captioned MP4 is exactly 150 seconds, with 276 scripted words and a real local-validator payout shown in Explorer. The Android release compiled against the stable API 37.0 SDK and targets API 36 on arm64 devices. APK signature verification passed, its certificate matches the website identity, and its package permissions were checked. It is a signed development release with optional minification disabled. A physical Seeker test remains unperformed. Hosted media checks are recorded in the final report. No physical Seeker test has been performed.

The public website keeps devnet and the local demo separate. The intended public devnet program is not yet deployed because the wallet has no free test SOL. The local demo executes the actual compiled program on its own validator and has its own database. Its Explorer links select the custom HTTPS RPC. Older local receipts can be pruned by the bounded ledger. The video captures a fresh readable receipt.

Local transactions are not public devnet transactions. A sample illustration is not a site visit. A wallet signature binds bytes to a wallet, not to an authentic camera sensor, GPS reading, student identity, or safe listing. Compilation and passing checks do not establish a security audit.
